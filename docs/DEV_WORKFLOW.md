# forkAI 开发与发布流程

日常按下面走即可，不必一开始就搞很重的规范。

## 1. 功能分支 + PR

1. 从主开发分支（当前是 `new`）拉新分支，例如：
   - `feat/车况查询`
   - `fix/tts-autoplay`
   - `chore/更新部署脚本`
2. 在分支上开发、提交。
3. 开 **Pull Request（PR）**，目标分支选 `new`。
4. 自己或同事 review 后合并。

**为什么用 PR：** 改动有记录、方便 review、出错可回退，也方便以后写月度总结（按合并的 PR 归类）。

## 2. Tag + Release

当一批功能可以对外/对内交付时：

1. 确认目标提交已合进 `new`。
2. 打 **tag**，版本号建议语义化：
   - `v0.1.0` 首发 / 小版本能力集合
   - `v0.2.0` 新功能
   - `v0.2.1` 修 bug
3. 基于该 tag 发 **GitHub Release**，写上本版变更要点。

当前已有首发：[`v0.1.0`](https://github.com/lovingQi/forkAI/releases/tag/v0.1.0)。

## 3. 和助手协作时怎么说

- 「总结这个月」→ 按提交 / PR 写功能总结
- 「打个 v0.2.0」→ 起草 release 说明并创建版本
- 「帮我开 PR」→ 从当前改动建分支并提 PR

## 分支约定（简版）

| 前缀 | 用途 |
|------|------|
| `feat/` | 新功能 |
| `fix/` | 修复 |
| `docs/` | 文档 |
| `chore/` | 工程 / 流程 / 依赖 |
