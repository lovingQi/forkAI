背景与场景

为什么做 · 谁在用

现场问题

  • 厂区弱网 / 无网，云端语音不可依赖
  • 操作员需要近场语音点动与参数化任务，而非纯遥控 App
  • 运动指令必须经过确定性安全层（锁、看门狗、急停联动）

用户与权限

  • 现场操作员（主）：车载屏 / 扫码浏览器 · 点动+任务+任务流
  • 车载麦克风：唤醒词武装后同等现场能力（窗口约 30s）
  • 远程用户：可任务 / 问答，不可点动（无现场锁）

核心场景（压缩）

  • 近场点动：扫码解锁 → 前进/转/停 → 看门狗 2s 无续令自停
  • 语音六任务：货叉 / 旋转 / 点到点 / 栈板 / 充电等，缺参追问
  • 任务流：可视化编排 → 语音触发 → 暂停/继续/取消
  • 车况问答：电量、模式、告警与处置建议
需求范围

做什么 · 不做什么

做（V2 范围）

  • 全离线 ASR / NLU / TTS（本地模型）
  • 六任务参数化下发与确认
  • 任务流编排 + 语音触发执行
  • 配对、现场锁、分级权限
  • 点动看门狗、急停退锁等安全闭环
  • 目标部署 RK3588 工控机

不做 / 边界

  • V1 栈冻结：voice-gateway / speech / forkweb 不演进
  • 智能绕障：由车端 jarvis，forkAI 不实现
  • 远程点动：明确禁止
  • 语音「停」≠ 实体急停
  • 仅中文普通话；不录音频

需求事实来源：docs/requirements-v2.md（PRD 为整合重述）。

架构 · 安全边界

LLM 不直控车 · 确定性保护

控制链路

  • 语音/文本 → ASR 纠偏 → 规则 NLU 优先 → LLM 兜底
  • 意图白名单校验；复合句最多拆 3 动作
  • executor：锁检查 → 对话/执行 → jarvis route / control
  • LLM 不可达时自动降级纯规则

安全要点（对外可讲）

  • 运动类：需 配对 + 现场锁；问答一般仅配对
  • 点动看门狗约 2s无续令自动停车
  • 实体急停上升沿 → 强制退出现场锁
  • 说「停 / 急停」是软件停止意图，不替代物理急停钮
  • 任务流 running 时拒绝新的运动级点动（STOP/查询仍放行）
