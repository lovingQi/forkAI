## 1. 产品形态

车载屏和手机使用同一套 Web。两端都能看全部页面。遥控、货叉、改参数只有持有现场锁的一端能做。急停在所有已接入终端上始终可用。车载屏可以二次确认后强制收回现场锁，对方立即失去控制并看到「控制权已被收回」。

车载屏的判定是两条同时满足：请求来自本机回环地址，并且带有 core 生成的 `services/core/data/console/kiosk.token`。入口是 `http://127.0.0.1:19000/?kiosk=<口令>`。只看 127.0.0.1 不够，因为开发时代理过来的请求也像本机。

没有车载屏配对时，已配对终端输入现场码并确认后可以抢占或结束现场。一旦有车载屏配对，手机不能强制抢锁，也不能强制结束现场，只能由车载屏收回，或等对方释放、超时。`console.allowRemoteForce=true` 时，即使有车载屏，手机也可以抢占。默认仍为 `false`。

## 2. 开箱

1. 每次打开网页都先播放约 8 秒全屏品牌动画：箱门打开，叉车沿坡道驶出并朝镜头开来，停稳后镜头一镜到底推进车上屏幕。公司全称只出现在箱面和屏幕边框。动画期间不自检。动画结束后进入静态开机页，再检查 core、jarvis、rosbridge。core 或 jarvis 失败就停在这一页并显示原因，可重试；重试不重播动画。rosbridge 一期固定为「二期接入」，不参与通过判定。系统设置了减少动态效果时，跳过动画，直接进入静态开机页。系统级开机画面仍等硬件定了再做。
2. 首次开机、向导未完成时，车载屏显示二维码，并提供「在本屏继续」。之后从顶栏「手机接入」打开二维码。
3. 二维码是访问地址加一次性凭证，120 秒有效，用过即废，新签发顶替旧的。手机扫码同时完成配对和现场解锁，这一步视为车载屏把控制权转交出去。
4. 初始向导只在首次强制出现。步骤是车辆信息、避障参数、传感器、完成。参数默认只读，修改走参数页的全套保护。确认后写入完成标记。参数页可以重新运行向导。完成向导只需已配对，重置向导需要控制权。

配网和车载屏硬件选型暂缓。在此之前，车必须由其他方式先连上 WiFi，扫码才能用。

## 3. 页面

六个页面：主页、建图、基本控制、参数、问题分析、任务流。横屏左侧导航，宽度小于 900px 时底部标签。急停常驻顶栏。沿用战术终端风格。建图和问题分析一期是「即将上线」占位。

### 基本控制

- 八个方向都保留：前进、后退、前进左转、前进右转、后退左转、后退右转、原地左转、原地右转，加上停止。按住才走，约 200ms 重发一次，松手、失焦、页面隐藏或离开页面立即停。断网由原有 2 秒看门狗停车。
- 速度滑块与语音点动共用 trans 幅度：100 到 1000 mm/s，步长 50，默认 500。关闭避障时上限 300。转向幅度沿用 `drive.rot=50`。
- 避障默认开（safedrive）。只能在车停稳时切换。关闭要二次确认。松开按钮、离开页面、5 秒无操作、控制权变更或急停，立即恢复避障。core 启动时强制恢复避障。
- 货叉升降沿用现有 `fork` 配置（75 到 210，步长 50）。伸缩 0 到 min(640, 车端上报的 fork_max_dis)，步长 50，容差 5。没有 `fork_cur_dis` 就不显示伸缩。步进或目标位置，差值超过 100 要再确认。车体和货叉互斥。
- 软件急停：停车、取消任务流、关电机、恢复避障。不弹确认。解除需要控制权并二次确认后再使能电机。界面写明不替代物理急停。车端 alarm 变为 estop 时仍退出现场锁。
- `/api/control/motor` 和 `/api/control/safe` 一律拒绝，避免绕过这些门控。

### 参数

有中文说明的 7 段（avoid、各 laser、robot）可改，并按 ranges 校验。其余段只读，放在「高级」。保存需要控制权、车静止、改动对比后二次确认。写入前自动备份，最多 50 份，可一键恢复，并记修改日志。avoid 段按车端语义整段下发，避免只改一项把其余项清掉。

### 建图

建图计算由感知同事部署在同一台 RK3588 上的引擎程序完成：2D 是 Cartographer，3D 是 Traverse。每个建图任务由 forkAI 拉起一次引擎。车上传感器经 Foxglove Bridge（ROS1）进入本机的 forkai-mapping（127.0.0.1:19010）。浏览器只访问 forkai-core，由 core 做配对鉴权和现场锁门控后再代理。

页面按车载场景收敛：2D/3D 页签，新建（离线、在线）和增量（扩建、更新局部）。未支持的入口显示为灰色禁用。第一阶段只做 2D 在线。建图页内嵌和基本控制相同的点动，沿用现场锁、速度上限和看门狗；不提供避障开关和货叉。急停只停车，不取消正在进行的建图。打点仍用现有 mark_point，本阶段不做。

地图先存在 forkAI 本机。导出的 ZIP 按 robospace 能导入的二维工程格式，只含 project.json、map.json 和 mapping_state.mcap。怎么交给 jarvis 使用以后再定。

### 问题分析（本期不做功能）

问题分析包含故障列表、部件自检、诊断包。故障中文表由 forkAI 起草、车端审核。AI 分析全部交给外部日志分析项目，接口未定。

## 4. 分期

- 一期：外壳、开机自检、扫码接入、向导、基本控制、参数。只依赖现有 jarvis HTTP。
- 二期：rosbridge、故障、自检、诊断包。
- 三期：建图页按 2D 在线、2D 离线、2D 增量、3D 在线、3D 离线、3D 增量推进；外部 AI 分析仍等接口。

一期和现有 MVP 共用真车测试窗口。一期软件验证最高到 Mock 和浏览器，不关闭真车待验项。
