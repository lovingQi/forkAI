## 任务简报

总负责人先建立任务简报，不完整时只做勘察，不进入实施。简报包含：

| 字段 | 要求 |
|---|---|
| 目标 | 描述用户最终需要的可观察结果 |
| 非目标 | 明确本次不处理的范围 |
| 仓库与模块 | 列出允许读取和修改的边界 |
| 当前事实 | 引用代码、文档、日志、提交或设备状态 |
| 验收条件 | 使用可检查的行为、指标或证据 |
| 风险等级 | 标记 L0、L1、L2 或 L3 及理由 |
| 部门分工 | 指定主责部门、协作部门和各收口负责人 |
| 用户批准点 | 标记需求、安全、架构、真车与部署决策 |

任务涉及 forkAI 时，建立简报前必须读取 `docs/project-ledger.md`，在简报中标注任务所属阶段与编号、相关任务当前状态、关联风险与测试日余量（规范见 `.agents/skills/forkai-ledger/SKILL.md`）。

## 阶段流程

```text
需求进入
  -> 只读勘察
  -> 风险分级与部门路由
  -> 需求/方案/验证矩阵会签
  -> 用户批准点（需要时）
  -> 边界化实施
  -> 分层验证
  -> 部门负责人评审
  -> 跨部门会签
  -> 总负责人收口
```

### 1. 需求进入

让产品与验收部把原始描述转换为目标、非目标、场景和验收条件。保留原始需求，建立从需求到设计、代码和测试的追踪关系。

### 2. 只读勘察

读取相关 `AGENTS.md`、工作区状态、代码、文档、测试、配置与 Git 历史。区分已实现、已验证、文档声称和未知状态。不得在勘察阶段写入文件。

### 3. 分级与路由

由总负责人确定风险等级。依据 `task-routing.md` 指定一个主责部门、所有受影响部门、执行成员和负责人。L2/L3 必须由系统架构部参加；物理动作必须由车端协议部与功能安全部参加。

### 4. 方案与验证会签

让主责部门给出方案、备选方案、影响面和回滚思路。让产品与验收部固定验收条件，让质量与发布部建立验证矩阵。负责人在实施前给出签署结论；L3 等待用户明确批准。

### 5. 边界化实施

把互不冲突的文件范围交给不同执行成员。要求每个成员只实现已批准内容，保留用户已有变更，报告实际差异。发现范围、假设或安全语义变化时停止并返回会签阶段。

### 6. 分层验证

依据 `quality-gates.md` 执行静态、单元、契约、Mock、E2E、HIL、真车、性能和部署验证。记录命令、环境、版本、输入、输出和未执行原因，不用较低层证据冒充较高层证据。

### 7. 部门评审与返工

向负责人提供原始需求、批准方案、差异、测试输出和风险登记。负责人逐项比较后给出结论。`有条件通过` 必须有关闭条件；`驳回` 返回对应责任成员返工，返工后重新验证和签署。

### 8. 会签与总收口

收集全部受影响部门结论。总负责人检查追踪关系、必需门禁、用户批准点和 P0/P1 风险，只在条件满足时宣布完成。

## 部门生命周期

每个部门按同一生命周期工作：

```text
进入：收到任务简报和明确边界
执行：成员产出分析、方案、代码或证据
评审：负责人核对合理性、完整性和风险
返工：对驳回项修正并重新验证
退出：负责人签署并明确交接条件
```

部门退出前必须回答：输入是否完整、方案为何合理、是否越过职责边界、证据覆盖了什么、还有什么未知、下一部门可以依赖什么。

## 会签与冲突

| 场景 | 必需会签 |
|---|---|
| 用户可见行为或话术变化 | 产品与验收部 + 对应实现部门 |
| 跨服务或跨仓接口变化 | 系统架构部 + 车端协议部 + 应用工程部 |
| 车辆运动、货叉、任务或恢复语义 | 车端协议部 + 功能安全部 + 质量与发布部 |
| ASR/NLU/LLM/TTS 变化 | AI 语音部 + 产品与验收部 + 质量与发布部 |
| 任务流并发、暂停、恢复或故障处理 | 系统架构部 + 应用工程部 + 功能安全部 |
| ARM、systemd、离线模型或发布变化 | 质量与发布部 + 系统架构部 + 对应实现部门 |

负责人意见冲突时，总负责人先要求各方引用事实、风险和验收条件，不以多数表决代替技术判断。安全部驳回时不得继续发布。需求、架构、安全或真车边界无法在已批准范围内解决时，提交用户决定。

## 总负责人收口

总收口必须包含：

1. 任务目标及最终状态。
2. 参与部门、执行成员和负责人结论。
3. 修改文件和跨仓契约变化。
4. 已执行验证及证据等级。
5. 未执行验证及原因。
6. 遗留风险、负责人和关闭条件。
7. 需要用户继续批准的动作。

8. 涉及 forkAI 的任务，收口时必须按 `.agents/skills/forkai-ledger/SKILL.md` 更新 `docs/project-ledger.md`（任务状态/测试日消耗/证据链接/阻塞/更新时间），未更新台账视为未收口。

存在缺失签署、失败门禁、未关闭 P0/P1 风险，或把 Mock 结论用于真车宣称时，总负责人必须拒绝收口。
