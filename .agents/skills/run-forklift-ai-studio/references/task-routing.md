# 任务路由矩阵

## 路由步骤

1. 从用户目标识别所有变更类型，不只按首个文件分类。
2. 指定一个主责部门和一个主签负责人。
3. 启用完成实际工作所需的临时专家。
4. 加入所有受影响部门负责人，不省略安全、协议或质量复核。
5. 使用表中默认等级；出现更高风险条件时上调。

## 常见任务

| 任务类型 | 默认等级 | 执行专家 | 主责/主签 | 必需协作或复核 |
|---|---:|---|---|---|
| 需求澄清、范围、验收 | L0-L1 | 需求分析、叉车业务 | 产品与验收部负责人 | 系统架构部、质量与发布部 |
| 架构重构、新服务、跨仓边界 | L2-L3 | 架构、API、可靠性 | 系统架构部负责人 | 产品、车端协议、应用、安全、质量 |
| Jarvis HTTP/WS 状态或 route | L2-L3 | 车端协议、C++/ROS | 车端协议部负责人 | 架构、应用、质量；物理动作加安全部 |
| 车辆运动、货叉、充电、避障 | L3 | ROS 控制、车型、HIL | 车端协议部负责人 | 功能安全部主签安全，质量部验证，用户批准 |
| 急停、看门狗、锁定、故障恢复 | L3 | 安全、控制、故障注入 | 功能安全部负责人 | 车端协议、架构、应用、质量，用户批准 |
| ASR、热词、纠偏、噪声 | L1-L3 | ASR 声学、ARM 性能 | AI 语音部负责人 | 产品、质量；真机测试升 L3 |
| NLU 规则、槽位、LLM、Prompt | L1-L2 | NLU/LLM 评测 | AI 语音部负责人 | 产品、应用、质量 |
| TTS、提示音、打断、音频播放 | L1-L3 | TTS/音频、前端 UX | AI 语音部负责人 | 应用、产品、质量；车载实测升 L3 |
| FastAPI、会话、Executor | L1-L3 | Python 后端 | 应用工程部负责人 | 架构、质量；动作/锁定加协议和安全 |
| 任务流 Schema、状态机、并行 | L2-L3 | 任务流、后端 | 应用工程部负责人 | 架构、质量；恢复/运动加安全和协议 |
| Vue、监控、地图、流程编辑器 | L1-L2 | 前端 UX、E2E | 应用工程部负责人 | 产品、质量；接口变化加架构 |
| Mock、契约测试、E2E、故障注入 | L1-L2 | QA、契约、E2E | 质量与发布部负责人 | 对应领域负责人 |
| RK3588、systemd、离线部署、回滚 | L2-L3 | ARM、DevOps、性能 | 质量与发布部负责人 | 架构、AI/应用领域负责人，目标机操作需用户批准 |
| 文档、API 表、话术表、测试报告 | L0-L2 | 技术文档 | 内容所属部门负责人 | 产品与验收部、质量与发布部 |
| 代码审查或交付审查 | L0 | 独立领域评审专家 | 对应部门负责人 | 质量部；安全相关加功能安全部 |

## 触发升级

出现以下任一条件时提升为 L3 并等待用户批准：

- 改变用户可见需求、任务含义或验收标准。
- 改变安全保护、速度、现场锁、动作恢复或故障降级。
- 需要向真实车辆或目标工控机写入、启动、停止、部署或发出动作。
- 需要新增/删除核心服务、替换框架或跨仓迁移职责。
- 无法从源码确认协议，需要通过真实车辆探索未知行为。

## Agent 任务单

总负责人向每个执行 Agent 提供以下字段：

```text
角色与部门：
任务目标：
允许读取范围：
允许修改范围：
禁止事项：
必须遵守的 AGENTS.md：
输入事实与原始证据：
预期交付物：
必须执行的验证：
需要升级的条件：
```

向独立评审 Agent 提供需求、批准方案、原始差异和测试输出，不提供实现者的自我结论或预期答案。评审 Agent 按严重度报告问题，并明确 `通过`、`有条件通过` 或 `驳回`。

## 并行规则

- 并行执行互不依赖的只读勘察、测试设计和不同文件域实现。
- 不让多个 Agent 同时修改同一文件或同一协议定义。
- 先确定契约，再并行实现生产者与消费者。
- 安全评审和质量评审保持独立，不把实现 Agent 的结论当作签署。
- 子任务完成后由总负责人重新读取共享工作区，处理用户或其他 Agent 的新变更，不覆盖未知改动。
