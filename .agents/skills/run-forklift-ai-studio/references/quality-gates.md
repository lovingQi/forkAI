## 证据等级

| 等级 | 环境 | 可以证明 | 不能证明 |
|---|---|---|---|
| E0 | 文档与静态分析 | 设计一致性、类型、格式、显式规则 | 运行行为 |
| E1 | 单元或离线测试 | 局部算法、规则、转换和异常分支 | 服务集成与车辆行为 |
| E2 | 契约测试与 Mock | 服务链路、协议结构、状态机模拟 | 真车实现、现场噪声、真实时序 |
| E3 | 浏览器 E2E 或服务集成 | 用户流程和多组件集成 | 真实车辆物理结果 |
| E4 | HIL/台架 | 目标接口、部分硬件与故障行为 | 完整现场工况 |
| E5 | 真车现场 | 指定车型、现场和用例的物理行为 | 未测试车型和长期稳定性 |
| E6 | 目标硬件部署/耐久 | RK3588 性能、离线部署、稳定运行 | 未覆盖环境的泛化结果 |

报告结论时标记证据等级、设备、车型、软件提交、配置、日期和操作者。不得从 E2 推断 E5，不得从 x86 推断 RK3588。

## 通用门禁

| 门禁 | 必要检查 | 失败处理 |
|---|---|---|
| G0 范围 | 目标、非目标、验收、风险和负责部门已固定 | 返回需求阶段 |
| G1 设计 | 方案、接口、单位、状态、失败路径和回滚已评审 | 返回方案阶段 |
| G2 实现 | 差异仅在批准范围，未覆盖用户改动，无冻结区越界 | 返工或重新审批 |
| G3 静态/单元 | 格式、类型、构建、局部测试通过 | 修复后重跑 |
| G4 契约/Mock | 跨模块契约、失败分支和回归通过 | 阻止集成收口 |
| G5 E2E | 用户关键流程、UI 状态和音频链路通过 | 阻止用户流程收口 |
| G6 HIL/真车 | 必需车型动作、安全恢复、状态语义有现场证据 | 标记未完成，不得冒充通过 |
| G7 部署/耐久 | 目标硬件安装、启动、性能、日志、回滚和耐久通过 | 阻止发布收口 |

只执行与变更相关的门禁，但必须解释跳过理由。安全关键或 L3 任务不得跳过 G0-G2；发布真车能力时不得跳过适用的 G6-G7。

## 变更验证矩阵

| 变更类型 | 最低软件证据 | 可能需要的现场证据 |
|---|---|---|
| ASR 模型、端点、热词、纠偏 | 离线语料、噪声、RTF、回归 | 目标麦克风、现场噪声、RK3588 |
| NLU 规则、槽位、Prompt、LLM | 黄金语料、边界/歧义、降级、复合指令 | 真实人声语料与现场站点名 |
| TTS、提示音、打断、播放 | 音频格式、回退、浏览器链路、回归 | 车载扬声器听感与噪声可懂度 |
| Executor、会话、锁定、安全 | 单元/回归、故障注入、并发与超时 | 急停、看门狗、锁定恢复 |
| Jarvis HTTP/WS 或 route | 源码核对、契约测试、Mock 对齐 | 指定车型的下发与完成语义 |
| 任务流状态机 | Schema、分支、暂停/恢复、断网、快照、回归 | 两条完整真车流程及异常恢复 |
| 前端或流程编辑器 | typecheck、构建、目标 E2E、响应式检查 | 车载屏幕与实际操作流程 |
| 部署、模型、systemd | 安装逻辑检查、干净环境冒烟、回滚 | RK3588 离线安装与耐久运行 |
| C++/ROS 控制或设备代码 | 构建、静态审查、仿真/回放、针对性测试 | HIL、低速隔离区、逐级真车验证 |

## 负责人签署矩阵

| 交付物 | 主签负责人 | 必需复核 |
|---|---|---|
| 需求与验收基线 | 产品与验收部负责人 | 主责实现部门负责人 |
| 跨模块/跨仓设计 | 系统架构部负责人 | 车端协议部、应用工程部 |
| 车端协议与车型语义 | 车端协议部负责人 | 系统架构部、质量与发布部 |
| 安全分析与保护策略 | 功能安全部负责人 | 车端协议部；用户批准 L3 |
| AI 语音方案与指标 | AI 语音部负责人 | 产品与验收部、质量与发布部 |
| 应用实现 | 应用工程部负责人 | 质量与发布部；涉及安全时安全部 |
| 测试报告与证据等级 | 质量与发布部负责人 | 对应领域负责人 |
| 工作室最终交付 | 工作室总负责人 | 全部受影响部门负责人 |

负责人参与实现时，复核人必须来自另一个受影响部门。测试作者不得作为唯一测试签署人。真车执行者可以记录结果，但质量与发布部负责人必须独立检查证据。

## 缺陷与风险

| 等级 | 定义 | 收口规则 |
|---|---|---|
| P0 | 可能导致人身、车辆、货物重大危险或失控 | 立即停止，必须关闭 |
| P1 | 核心功能错误、数据破坏、无安全降级或高概率任务失败 | 发布前必须关闭 |
| P2 | 有替代路径的功能或性能问题 | 明确责任人与关闭条件 |
| P3 | 低影响体验、文档或维护问题 | 可登记后续处理 |

所有失败测试都必须记录，禁止只展示通过项。无法执行的验证标记为 `未验证`，不得标记为 `通过` 或从报告中删除。
