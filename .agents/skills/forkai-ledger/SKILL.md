# forkAI 项目台账读写规范

台账文件：`/home/xbl/Desktop/learn/forkAI/docs/project-ledger.md`（执行状态唯一动态事实来源）。计划基线 `docs/project-plan-v2.md` 已冻结，任务定义（名称/测试日预算/准出标准）以基线为准，本 Skill 不得修改。

## 1. 何时读取

- 工作室（run-forklift-ai-studio）建立任务简报时**必读**台账：确认本次任务所属阶段与编号、相关任务当前状态、是否存在阻塞、测试日余量是否覆盖本次现场工作。
- 用户询问项目进度、里程碑、测试日消耗或阻塞时必读，禁止凭记忆回答。
- 读取后在任务简报中标注：涉及的任务编号、其当前状态、关联风险项。

## 2. 何时更新

- 工作室**总收口阶段**更新，且仅当任务有实际进展（开始/完成/阻塞/解阻/消耗测试日）。
- 不得为"保持同步"而做空更新；不得提前登记尚未发生的进展。
- 更新后向用户口头汇报变更了哪些行。

## 3. 允许更新的字段（仅此六类）

1. **状态**：见第 4 节状态机。
2. **测试日消耗**：任务表"测试日（预算/消耗）"的消耗值；同步更新 §1 阶段总览的消耗与合计。
3. **证据链接**：指向测试记录、报告、日志或文档的路径（如 `docs/test-report.md`、回归输出摘要位置）。
4. **阻塞原因**：状态为"阻塞"时必填；解阻时清空。
5. **更新时间**：更新当日日期（YYYY-MM-DD）。
6. **里程碑/风险状态**：§2 里程碑"状态/达成日期"；§4 风险"状态"（开放/关闭/接受）与备注。

## 4. 状态机

```
未开始 → 进行中 → 已完成
            ↓↑
           阻塞（解阻后回 进行中）
```

- 任务进入"进行中"：登记更新时间。
- 任务标"已完成"：**必须先满足第 5 节证据铁律**。
- 阶段状态随任务推进更新（全部任务完成且里程碑签字 → 阶段"已完成"）。

## 5. 证据铁律（与根 AGENTS.md、quality-gates 一致，不得放宽）

- 标"已完成"必须填写证据链接，且证据等级满足该任务准出标准：
  - 准出标 E4 的任务：HIL/台架记录；
  - 准出标 E5 的任务：真车现场记录（车型/场地/日期/操作者）；
  - 准出标 E6 的任务：RK3588 目标硬件记录。
- **E2 Mock 证据不得关闭 E4/E5/E6 任务**；Mock 回归通过不构成真车项完成。
- 未执行的验证标"未验证"，不得标"通过"或从记录中删除。
- 真车/目标机任务还需满足前置记录要求（车型、载荷、场地、人员、急停、速度上限）。

## 6. 冻结纪律

- 不得修改任务名称、负责方、测试日预算、准出标准、阶段结构。
- 新增任务、修改任务定义、调整阶段边界 = **计划变更（L3）**：必须取得用户明确批准，在 §5"计划变更记录"登记（日期/内容/批准人），必要时同步修订基线 `project-plan-v2.md`（修订本身也需用户批准）。
- 里程碑签字（M0–M5）只能由用户批准产生，AI 不得自行勾选。

## 7. 更新示例

任务 1-1 真车 route 语义验证完成时，该行由：

```

```

更新为：

```
| 1-1 | 真车 route 语义验证（…） | AI+人 | 1/1 | 已完成 | 实测记录，映射确认或修正（E5） | docs/test-report.md#route-语义 | | 2026-08-20 |
```

同时：§1 总览 MVP 期测试日改为 `4/1`；若发现判定映射需修正，§4 风险 R-01 备注登记，但不许改任务定义。

## 8. 每日简报（只读）

用户说"每日简报"（精确触发词，同义词不触发）时，读取台账并按下述固定模板输出。本操作**只读**：不更新台账任何字段，不消耗测试日，勾选不了里程碑。

### 数据准备

读取台账 §1 阶段总览、§2 里程碑、§3 全部任务表、§4 风险表，全部结论由数据机械计算，禁止凭记忆或推测补全。

### 输出模板（固定三段，结构不得自由发挥）

```
【每日简报 · YYYY-MM-DD（当天日期）】

■ 进度
<20 格 ASCII 进度条：█=已完成比例，░=未完成> NN%（x/34 任务完成；测试日消耗 y/23）
一句话：<当前阶段名称> <该阶段已完成数>/<该阶段总数> 项完成。

■ 下一个任务
[<编号>] <任务描述>
负责方：<负责方>｜测试日预算 <n>｜准出：<准出标准>
（如有被跳过的阻塞任务，追加一行：⛔ 已跳过 <编号>（阻塞原因：…））

■ 项目位置
| 阶段 | 状态 |
|---|---|
| 阶段 0 就绪期 | ✅ 已验收（M0）/ 🔵 进行中 / ⚪ 未开始 / ⛔ 阻塞 |
| MVP 期 | … ◀ 当前位置 |
| 增量期 / Demo 期 / 优化期 / 验收期 / 阶段 6 交接 | … |

数据来源：docs/project-ledger.md（以台账更新时间为准）
```

### 口径规则

- 进度条：34 项任务等权，█ 格数 = round(已完成数/34×20)；测试日消耗取 §1 合计行。
- 下一任务：按阶段顺序、编号顺序取第一个"未开始或进行中且未阻塞"的任务；无可做任务（全部完成或全阻塞）时如实说明，不得编造。
- "已验收"只以对应里程碑（M0–M5）被用户勾选为准，不得按任务完成度推断；阶段"进行中"/"未开始"/"阻塞"随其任务状态判定。
- 当前位置 = 第一个非"已完成"的阶段，标 `◀ 当前位置`。
